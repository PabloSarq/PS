LÁMINA 02

Arquitectura del sistema

Beta en un servidor local dentro del estudio: costo cero y los datos quedan en una máquina propia. Se usa desde la PC del estudio o el celular, sin instalar nada.

Usuarios

  • Profesionalcarga el día, ve su mes
  • Managerdatos maestros, aprobaciones, informes
  • Socio / lecturasolo informes
→

Acceso

  • En el estudiored local, directo al servidor
  • Desde casa u obraCloudflare Tunnel, gratis, sin abrir puertos
  • Conexión cifradahttps con el dominio del estudio
→

Servidor del estudio

PC o notebook propia · Docker
  • App webNext.js · login y roles propios
  • Base de datosPostgreSQL estándar, portable
  • Fecha del servidorzona America/Argentina/Tucuman
  • Cierre automático 23:59tarea programada diaria
  • Auditoríaquién cambió qué y cuándo
→

Salidas

  • Dashboard web
  • Excel y PDF A4por proyecto y por mes
  • Email 18 h"no cargaste hoy"
  • Backup nocturnocifrado, al Google Drive del estudio

Costo de la beta: USD 0 (máquina existente + servicios gratuitos). Requiere un dominio; si el estudio ya tiene uno, no suma costo.

Riesgos aceptados: un corte de luz o de internet en el estudio frena la carga mientras dure. El mantenimiento queda a cargo del estudio. Si la beta se consolida, se muda a la nube o a un equipo dedicado sin reprogramar.

LÁMINA 04

Modelo de datos

Nueve tablas. El centro es registros_horas: una fila por persona, día, proyecto y tipo de hora.

miembros

  • id
  • nombre, email
  • rol
  • jornada_diaria
  • tope_extras_mes
  • activo

contrato_mensual

  • miembro_id → miembros
  • año_mes
  • horas_contratadas

tarifas

  • miembro_id → miembros
  • tipo: ordinaria · extra50 · extra100
  • costo_hora (costo estudio)
  • vigente_desde / hasta

registros_horas

  • id
  • miembro_id → miembros
  • proyecto_id → proyectos
  • fase_id → fases
  • fecha · horas
  • tipo: ordinaria · extra50 · extra100
  • cargado_por → miembros
  • nota

auditoria

  • quién, qué, cuándo
  • valor_anterior → valor_nuevo

proyectos

  • id, código
  • nombre, cliente
  • estado
  • horas_presupuestadas
  • interno (sí/no)

fases

  • proyecto_id → proyectos
  • nombre

asignaciones

  • proyecto_id → proyectos
  • miembro_id → miembros

feriados

  • fecha
  • descripción
  • ámbito: nacional · provincial · estudio
miembros 1 — N registros_horas proyectos 1 — N registros_horas miembros N — N proyectos (asignaciones) miembros 1 — N tarifas (por vigencia)

Costo de un registro = horas × tarifa vigente en esa fecha para ese tipo. Se calcula al armar el informe, así cambiar una tarifa nueva no altera meses cerrados.
